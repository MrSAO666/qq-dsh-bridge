# Token 与回复延迟优化

这次优化针对“普通 QQ 聊天反复携带长历史、收尾错误引起多次决策”的问题，不通过删除缓存命中 Token 或重置账本掩盖用量。

## 回复时间的两个选项

- `socialV2.send.firstReplyMinMs`：私聊从**最后一条来信**到机器人回复的最短等待。0 表示不额外限制；设 15000 表示至少 15 秒。模型读取、思考已经花的时间也计入；如果已思考 20 秒，不再额外等待 15 秒。等待期间补充消息，会从最后一条重新计时。
- `socialV2.send.burstIntervalMinMs / burstIntervalMaxMs`：机器人连发消息时的间隔。`enforceMinimumGap=true` 时，不同工具调用也遵守最短间隔，避免换一次发送工具就绕过间隔。最大值是自动分条的随机上界，不是保证必须在这个时间内发出。
- 群聊首答可通过 `firstReplyMinMsGroup` 独立配置，默认为 0。发送等待在桥接中执行，不产生模型轮询。暂停、模式或权限改变时会重新检查，取消在途发送。

## 收尾协议

`qq_send_message` 默认在所有消息确认发送成功后，同时确认发送开始前已展示的已读水位，并结束本轮。继续发表情或执行任务可传 `close:false`。只看不回仍可用 `qq_mark_read` / `qq_set_wake_config`。

省略水位的 Agent 调用只确认真正展示过的连续消息；只有管理端显式清空保留旧的全部清空语义。发送期间才到达的消息不被清除。后来的消息交给后台安排下一轮；同一未读水位最多额外补唤醒一次，防止“模型一直不读却不断收尾”循环。没有五分钟强制观察窗口。

## 上下文保护

默认软阈值 40,000 输入 Token，闲置 5 分钟后整理；下一次 QQ 唤醒或自动 B 站协调前，输入达到 80,000 时先压缩。默认仅用于私聊，可配置 `onlyPrivate`。正在执行的工具链不会被中途改写，阈值不代表当前模型请求的硬截断器。

按当前**父 sessionId**取最近输入，不能让同一 QQ key 的 B 站子会话掩盖父会话大小。压缩保留短尾部和摘要，会话 id、角色文件及长期记忆文件不变。已整理的同一采样不会再次触发；必须等下一次真实请求才能测得新上下文大小。失败会保留未读并显示原因、冷却五分钟，不会启动模型轮询。

Owner 预设的压缩尾部从 80k 降至 12k，摘要输出上限 4k；长工具结果裁剪阈值改为 8k。短时闲置整理前仍可先整理重要记忆；硬边界直接使用 DSH 的上下文摘要以免先用长上下文执行多轮记忆写入。

## 稳定人格与动态信息

角色、身份和令牌仍由现有上下文插件注入。普通记忆快照每会话固定在 1,800 字符内，压缩后可更新；新事实正常保存并通过 `qq_recall` 按需召回。表情列表改为按需查询，不随收藏变化不断刷新整个系统提示词。没有删除人格/记忆功能，也没有新增第三方插件。

DSH 的 DeepSeek 适配器使用 `in-history`，不能声称系统提示词天然不占历史。这次控制内容变化频率并整理已有历史，不私改 provider 的缓存策略。

## 图片与长文本

图片按内容哈希和 QQ 会话隔离。同一会话已经展示的图不重复返回原图，可通过 `force:true` 重读。模型可在发送回复时用 `imageNotes:[{hash,summary}]` 顺便保存图像描述；描述不跨会话共享，需本次会话实际看过原图才接受写入。没有描述的新会话必须重新看原图，不能凭空声称记得。描述保留 7 天，最多 1,000 条；模型描述是数据而非新指令。

网页默认返回 3,000 字符摘录，原文落本地有界文本库；用 `textRef + offset` 分段读取，不重复联网抓同一页。字幕默认每次 4,000 字符，可按 `BV + nextOffset` 读取后续。摘录不代表看完全部视频；无字幕继续跳过。文本库默认 100 项、合计约 2MB，保留 7 天。

## 每轮预算

在原有 `qq-agent-context` 内使用 DSH 实际支持的 `agent/pre-step` 与 `agent/request-error`，不是只写提示词。

| 配置 | 默认 |
|---|---:|
| 普通聊天模型请求 | 8 |
| 普通聊天累计输入 | 400,000 |
| 主人任务/后台 B 站父协调请求 | 40 |
| 主人任务/父协调累计输入 | 1,500,000 |
| B 站子任务请求 | 40 |
| B 站子任务累计输入 | 1,500,000 |
| 同一工具失败上限 | 2 |
| 连续模型失败上限 | 2 |

以上均在「回复节奏 → 上下文与执行预算」调整。预算按回合计，工具后续决策和允许的模型重试也算请求；输入按已完成请求的 usage 累计，允许已开始的一次请求完成，不能保证不超过单次输入的余量。达到后拒绝下一步，写明停止原因，保留未读，不反复唤醒模型要求它收尾。

主人需要执行复杂工作时开启「主人私聊使用任务预算」；不改变主人已有 Shell、文件、通用子 Agent 权限。B 站每日次数/时长、主动聊天每日额度互相独立，主人手动刷站的次数与时长豁免保持不变。思考强度没有自动降级。

预算与显式角色设置由上下文插件最多约 120 秒刷新一次；桥接发送等待和普通节奏配置直接使用当前配置。预算停止原因、压缩阻塞与上次输入大小显示在回复节奏页面「执行状态」。

## 金额与验证

有逐请求明细的历史按实际请求时刻和模型计价，只有缺乏明细的基线残差继续估价；累计、日期明细和时间轴使用相同口径。Token 桶及去重逻辑不变，金额始终是配置价目表的估算，实际扣费以服务商账单为准。

离线验证入口：`npm run test:token-optimization`、`npm run test:token`、`npm run test:tokens`、`npm run test:token-audit`。新验证覆盖：15 秒首答底线与补充消息重计时、并发未读保留、父子上下文隔离、压缩幂等、预算熔断、图片隔离与重读、文本分段及历史计价一致性。

部署后需要用真实请求的输入规模、每轮请求数和失败率做前后比较。不能把条件计算的节省比例当成已经实现的结果。
