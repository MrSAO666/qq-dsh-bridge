# B 站能力接入设计

## 目标与边界

在现有 QQ 桥接中增加 B 站浏览和互动能力，复用当前人格、记忆和 QQ 会话；不运行 dsh-bili-pond 的独立人格、记忆和 headless 值班会话。用户使用独立 B 站账号；允许 @ 的 UID 暂为空，空名单时禁止 @。允许评论和点赞，具体对象、频率和开关须在管理界面可配置。

## 已核实的兼容点

- 鱼塘 1.3.14 的 `index.js` 通过 `dsh --profile headless` 创建独立任务，不能视为主会话派生的 DSH 子 Agent。
- 当前 `qq-chat-owner` 预设已开放通用 subagent 工具；群会话与其他受限会话仍然拦截。主人预设的独立 DSH 会话已实测可以调用 subagent，现有 QQ 会话内的完整链路仍需验证。
- DSH 官方 subagent 的 spawn 使用独立会话，不能假设它自动拥有主会话历史或桥接记忆；需要主动传入经过裁剪的上下文。
- 鱼塘使用 Python MCP 服务、独立凭据、字幕获取和交互限制；本项目复用了其 B 站接口代码并保留许可证，使用服务器的独立 Python 虚拟环境。
- 云端已部署设置、扫码登录、自动任务、评论和点赞；首次真实自动任务已完成。子任务结果交给主 Agent，不再自动向 QQ 发送刷站汇报。

## 目标链路

自动计时器主动唤醒主人 QQ 主 Agent；主人也可以在 QQ 中直接要求刷站。主 Agent 通过已开放的 DSH 子 Agent 机制创建子任务 → 子任务以单并发调用受限的 B 站工具 → 结果以结构化短摘要交回父会话 → 父会话决定如何利用现有人格、记忆和 QQ 通道。

子任务输入：配置中的主题和内容来源、互动设置及受限工具策略。子任务向父会话汇报，不会另行向 QQ 发送报告。子任务不会自动继承主会话完整历史或桥接记忆；视频内容没有字幕时跳过。

## 权限与资源

- 使用单独 B 站登录凭据，保存于服务端受限文件中，不写入模型提示、日志或记忆。
- 浏览、点赞、评论分别受开关和每日限额控制。@ 尚未接入；即使设置了名单，目前也拒绝在评论中输入 @。互动在发出前预留额度；回执不能确认时记录为「不确定」，不自动重试。
- 通用子 Agent 仅在 owner 会话开放，其他会话仍被拦截；刷站子任务仅授予所需工具。外部字幕、简介和评论仅作为数据，不作为命令。
- 初期单任务并发；限制候选数、文本长度、模型 token、单轮耗时和每日交互次数。优先现有字幕；默认不启动本地语音识别。
- 运行记录和互动限额是独立的业务状态，不作为第二套人格或长期记忆。父会话会被提示参考现有人格和记忆，并自行判断是否将有价值的发现存入现有记忆；该行为尚未实测。跨轮的视频内容去重尚未接入。
- 子任务结果通过 DSH 返回父会话；不在 QQ 中另行投递报告。

## 自主刷站与主人主动调用

- 自动任务独立于已有主动聊天计时器；启用后无需主人发指令，不会向 QQ 自动发送刷站汇报。
- 桥接启动 30 秒后首次检查，之后每 60 秒检查一次。开关开启、当日额度未满、没有未结束任务、DSH 主人会话可用且空闲时，距离上次自动预约至少 `24 小时 / 每日上限` 才会派发。例如上限 5 次，对应最短间隔 4 小时 48 分钟；这是按上次预约时间推算的间隔，不是随机时刻，也不保证一天跑满。每日零点仅切换计数日期，不会清除跨日间隔。
- 设置页提供搜索关键词、关注 UP 主、推荐流等来源配置，以及自动刷站开关、每日最多次数、单次最长分钟数及运行状态。初始按用户指定：每天最多 3 次、每次最长 20 分钟，可在设置页修改。次数按北京时间自然日计算，自动任务启动前持久化预留名额；失败和重启不重复返还，以免绕开上限。
- 自动任务的计时从子任务实际开始执行计算；达到期限时由代码向该任务发中断并等待确认，记录超时。不能仅靠提示词让模型自觉结束，也不能在子任务未停止时启动下一轮。
- 主人在 QQ 主会话中主动要求刷站不会消耗自动任务次数，也不受自动单次时长约束；直接发起的任务尚未与自动任务做统一并发互斥。
- DSH 未就绪时不会派发任务；任务结束状态无法确认时不重复启动，并在重启后尝试恢复监听。B 站登录失效目前通过工具调用失败体现，调度前尚未主动校验。
- 首次运行、每日边界、并发竞争、用户主动请求、到时中断与失败恢复必须覆盖测试，并在接入真实子 Agent 后验证。
- 没有字幕的视频不看、不通过转写或画面理解补看；互动开关和次数上限分别可配置。子任务向主 Agent 汇报。
- QQ 在 02:00–08:00 离线时，DSH 仍可刷 B 站；不在 QQ 上线后补发刷站汇报。
